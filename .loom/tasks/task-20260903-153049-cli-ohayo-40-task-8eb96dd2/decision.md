# 결정

사용자의 현재 실행 지시와 회의의 마지막 정리(18:42, 40개·가로 스크롤 및 12:45, 총 20분)를 채택했다. 기존 Job의 10개 및 이전 Task의 40개 제외 문구는 당시 범위로 보존하고 새 후속 Task와 Job note에 변경 근거를 기록했다.

구성 200초는 유지하며 40개 × 5초로 배분했다. 실행은 40개 × 30초로 배분하고 각 실패·복구 이벤트도 30초 안으로 조정했다. 새로운 Task는 기존 10개 기능을 각각 4개 구현·검증 목표로 나누어 이름만 중복시키지 않았다.

Task의 의존성과 기능 묶음을 scenario 데이터에 두고 그래프·카운트·복원 상한은 데이터에서 계산한다. 가로 스크롤과 현재 Task 따라가기로 40개를 작은 글자로 한 화면에 축소하지 않는다. fallback은 별도의 스크롤 목록과 고정 현재 상태를 사용한다.

CLI 입력은 Unicode grapheme 단위로 줄바꿈·이동·삭제한다. 패널 높이는 터미널 높이 안으로 제한하되 원문은 보존하고 커서 이동으로 전체를 확인하게 했다. resize 시 이전 물리 행 수를 신뢰하지 않고 새 입력 블록을 렌더한다.

40개 제품 실행 저장 상태와 Presenter 채널을 v3로 분리하여 이전 10개 완료 상태가 새 결과로 복원되는 것을 방지했다. 원격 게시·실제 서비스 구축은 수행하지 않았다.
